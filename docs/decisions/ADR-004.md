# ADR-004 — C4 RSC shell, chrome, ContentMount, fixture site

Status: Accepted

Date: 2026-08-15

## Context

Step C4 builds the render path: the website route group, reserved-slug
chrome, ContentMount content execution, the inline gw bootstrap, and a
working fixture deliverable. Several mechanics needed fixed decisions.

## Decision

1. **Fixture site (deliverable):** `lib/data/providers/fixtures/` implements
   the DataProvider contract over in-memory fixture pages (home/about/detail
   + chrome + default-settings). It is a dev-only test double — NOT a
   database backend — selected exclusively by `GW_DEV_FIXTURES=1` (new
   optional env var; `.env.example` ships `0`). The resolver stack's
   `getProvider` honors it; tenant configs never reference it.
2. **Head-adjacent slots:** the gw bootstrap, `headCode`, theme CSS and
   analytics plugins render through the `ScriptSlot` client component, which
   appends real `<head>`/`<body>` script nodes after hydration (idempotent
   per slot id). Rendering `<script>` tags inside React components triggers
   React's "scripts never executed" warning and client re-render problems —
   ScriptSlot avoids both. Ordering guarantee: ScriptSlots mount and run
   before ContentMount's double-rAF content scripts (Section 12). Theme
   `<style>` stays inline (no React warning for styles).
3. **ContentMount (Section 11):** html injected via a `<template>` (embedded
   scripts never auto-run), embedded `<style>` hoisted to `<head>`,
   embedded `<script>` extracted and executed, `code.css` appended to head
   deduped per contentId, embedded scripts + `code.js` executed sequentially
   after double rAF inside an IIFE via Blob URL. Top-level function
   declarations are transformed to `window.fn = fn = function fn…` so they
   hoist to window (regex on column-0 declarations — documented
   approximation). Blob-script errors are isolated from the app shell and
   reported as `gw:script-error`; `gw:content-ready` fires after execution.
4. **SPA navigation:** one delegated document click listener for
   `[data-ic-nav-href]` + a window `ic-navigate` listener route through the
   Next.js router; content re-mounts (scripts re-run) on route change via
   effect dependencies.
5. **Preview (Q9):** `?gw-preview=<previewSecret>` enables draft pages;
   preview responses get `noindex`.
6. **404 correctness:** the plan's `loading.tsx` was REMOVED from the
   `(website)` group — with a loading boundary, Next streams the shell with
   status 200 before `notFound()` throws, masking the 404 ("no silent
   notFound masking", Section 9 step 8). Without it, unknown/draft paths
   return a true 404.
7. **Theme:** `theme.colors` → `--gw-color-<key>` CSS variables,
   `theme.cssVariables` as-is, `theme.cssClasses` as wrapper class tokens.
8. **Metadata:** built from the fixed SEO section; og/twitter fields are
   emitted only when their values are valid (Next validates the union types
   at runtime — invalid `type`/`card` crashes rendering, so they are
   filtered). JSON-LD payloads render via ScriptSlot (head) to avoid
   React's script-tag warning.
9. **Analytics snippets:** gtag/GA4, GTM (+ noscript iframe in body), Meta
   Pixel, ShareThis — ids restricted to `[A-Za-z0-9_-]+`.

## Consequences

- `pnpm dev` with `GW_DEV_FIXTURES=1` serves a full multi-page fixture site;
  e2e (Playwright, chromium) proves: pages render, scripts execute with
  hoisting, styles hoist, SPA nav re-runs scripts, no console errors.
- The plan's route tree lists `loading.tsx` — deviation recorded here;
  revisit if a pre-stream resolution step is added later.
- Slot scripts run post-hydration (not in the initial HTML payload); GTM/
  pixel/analytics semantics are unaffected, headCode timing shifts slightly
  later. Revisit if SSR-executed slots become necessary.
