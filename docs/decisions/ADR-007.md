# ADR-007 — Data access & operations API (C7 / M12+M13)

Status: Accepted
Date: 2026-08-15

Context:
C7 builds PART B's get/set fabric (Section 29) and the operations engine
(Section 30). The constraints from the plan: NO raw client writes anywhere
(operations are the ONLY set path), all storage through the DataProvider
interface (Section 6B), and every enforcement rule must be server-side
(Sections 32–33).

Decision:
- DataProvider extended (Section 6B): `createRecord` / `updateRecord` /
  `deleteRecord` on the provider plus a collection-scoped `DataTransaction`
  (`get/set/update/delete` over `{collection, id, data}`). The Firestore
  adapter implements both (`runTransaction` wraps a Firestore transaction);
  the fixture (dev) adapter stays read-only and throws on writes.
- Query fabric (POST /api/data/query, GET /api/data/{type}/{id}) with
  server enforcement in this order: traffic rules → hashed-IP rate limit
  (DATA_QUERY_RATE_MAX 120/60s, SHA-256 + RELAY_SECRET salt — raw IPs never
  stored) → strict Zod payload → site resolution → type access via
  cms-settings.objectTypes (publicAccess 'no' → 403; unregistered type →
  404 unless `tenant.parentTenants` is non-empty) → per-folder field
  allowlist (folder doc `data.fieldAllowlist`/`publicFields`, projection
  always keeps `id`) → 30s memory cache keyed `host|JSON(query)` → provider
  query → `meta.language` filter → per-record privacy
  (`rules.publicAccess === 'no'` filtered server-side).
- Search uses fuse.js (keys from the first result item, threshold 0.4,
  ignoreLocation); filters/facets/relations/sort/pagination run in the
  provider-neutral interpreter (lib/data/common).
- Operations engine (`lib/render/operations.ts`): operation definitions are
  loaded from the website app's objects (`data.operationId`, parsed with a
  tolerant schema). Execution order: idempotency replay → validation
  (JSON-schema subset: required + property types) → permission (roles;
  ownerField reserved) → formulas (SAFE expression subset) → multi-doc
  writes → hooks (never fatal).
- Formula DSL: numbers, strings, parens, `+ - * / %`, property paths, and
  ONLY whitelisted functions sum/count/avg/min/max/round/floor/ceil/abs/str.
  List-function item expressions are NOT evaluated eagerly: their token
  range is consumed and re-evaluated per list item with the item as an
  innermost scope (lazy evaluation).
- Context functions run in a sandboxed, reviewed subset: node:vm with ONLY
  Math/Date/JSON in scope and a 500ms timeout. `process`, `require`, `fetch`
  etc. are unavailable.
- Writes: `transaction: true` → `provider.runTransaction` (all-or-nothing,
  rollback on any failed write); otherwise sequential adapter writes.
  `by: {id: 'payload.items[].id'}` templates are resolved against the
  payload root (the `payload.` prefix is stripped); `with` templates support
  `user.*` and `payload.*`. Target collections are
  `${targetType}${tableExtension}`.
- Idempotency (Section 33): key from `Idempotency-Key` header or payload
  `idempotencyKey`; SHA-256 digest stored as an object of type
  'operation-results' with id `idem-<digest>`; replays return the stored
  result with `idempotent: true`. Result storage is best-effort.
- gw.db subscribe is a 5s polling fallback over POST /api/data/query
  (diff by id JSON → added/modified/removed) until C11 realtime.
- Same-origin guard fix (amends C6 guards): compare origin host vs request
  host port-insensitively via `normalizeHost` (raw `Host` header first,
  normalized `x-gw-host` fallback) — the proxy strips ports, which broke
  `localhost:3000` origins in dev.

Consequences:
- Vertical tools get exactly one generic GET path and one operation path;
  every write is CMS-contracted. Adapters keep Firestore collection/shape
  compatibility (Section 6).
- Fixture-mode e2e cannot exercise writes (read-only adapter) — emulator
  tests use a recording in-memory provider with the same assertions
  (tests/api/data-fakes.ts), runnable against the Firestore emulator when
  FIRESTORE_EMULATOR_HOST is available.
- Trade-off: formula DSL and sandboxed context functions are deliberately
  minimal; extending either is an explicit plan amendment (Section 0C).
- The polling subscribe is a known interim: replaced by realtime in C11.
