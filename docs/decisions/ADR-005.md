# ADR-005 — C5 window.gw SDK v2

Status: Accepted

Date: 2026-08-15

## Context

Step C5 ships the complete `window.gw` surface (Section 12): context,
navigation, storage, auth stubs, tracking, UI bridge, sanitize, formatting,
`gw.forms` (Section 14 client), `gw.db` stubs (Section 29), `gw.apps` stubs
(Section 35). The SDK must be isomorphic and injected as an inline bootstrap
script. The initial approach serialized compiled functions via
`Function#toString()` — and failed in the browser.

## Decision

1. **SDK source is an explicit string** (`lib/gw-sdk/sdk-source.ts`,
   `String.raw` template): Next's server compiler (Turbopack/SWC) rewrites
   compiled function bodies (hoisted `const` emitted as `undefined`, helper
   rewrites, mangled `dompurify.toString()` into `(root)=>createDOMPurify(root)`
   with the helper stripped). Serializing compiled functions is therefore
   UNSAFE. The SDK source is plain JS inside the template (no backticks/`${`),
   typed at the boundary by `types.ts`, and verified behaviorally by
   tests/gw-sdk/bootstrap.test.ts (generated source executed in happy-dom).
2. **DOMPurify is vendored** (`public/vendor/purify.min.js` from the
   dompurify dist, loaded via `ScriptSlot id="gw-dompurify"` before the
   bootstrap). `gw.sanitize` uses `window.DOMPurify` when loaded and degrades
   to a tag-stripping + escaping fallback otherwise. The `dompurify` npm
   dependency was removed (static vendor, no serialization).
3. **Form client contract (server in C6):** `POST /api/forms/submit` —
   multipart `FormData` when file inputs exist, else JSON
   `{ formTypeId?, submittedAt, gw_hp, values }`. Events (all BUBBLE so both
   form-level and window-level listeners work):
   `gw:form-success {form,data}` · `gw:form-error {form,error,status?}` ·
   `gw:form-invalid {form,errors}`. Honeypot (`gw_hp`/`website`/`company` or
   `[data-gw-honeypot]`) filled → silently dropped. Busy states via
   `.gw-busy` + `[data-gw-form-status]`. `bind(root?)` wires
   `form[data-gw-form], form.gw-form` idempotently.
4. **gw.db twins:** `query` → `POST /api/data/query`, `get` →
   `GET /api/data/{type}/{id}` (404 → null), `operation` →
   `POST /api/data/op {operation, payload}`; `subscribe` stub warns until
   C11 (C7 may add polling).
5. **gw.apps stub:** `register(name, factory)` + `mount(root?)` over
   `[data-gw-app]` + `data-gw-config` JSON; unknown app or factory throw →
   bubbling `gw:app-error`.
6. **Misc semantics:** storage keys `gw:v1:<host>:local:<key>` /
   `...:session:<key>`; `getPageParams` merges live URL params + context
   query + pathParams (pathParams win); `navigate` emits `ic-navigate`
   (handled by ContentMount's router.push) + fires `onRouteChange`;
   auth is a documented stub until C9; `gw.service(name)` rejects until the
   service endpoints land (C6/M9).

## Consequences

- Bootstrap is deterministic across compilers; the e2e suite proves the full
  surface in a real browser (storage, formatting, DOMPurify sanitize,
  `gw:form-error` on the not-yet-existing endpoint, no console errors).
- The SDK inner code is a string (no static type-checking inside); the
  boundary types + behavior tests are the contract. Prefer small edits
  + full test runs when touching sdk-source.ts.
