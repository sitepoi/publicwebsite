# ADR-006 — C6 forms v2 endpoints

Status: Accepted

Date: 2026-08-15

## Context

Step C6 builds `POST /api/forms/submit` and `POST /api/forms/upload`
(Section 14): the full guard chain, the saveForm-compatible write, the
server-side form-type config with afterSaveApiHooks, and storage uploads.
The Firestore emulator is not part of this environment, and forms must write
to ARBITRARY collections (`${destinationTable}${tableExtension}`), which the
C1 DataProvider interface did not support.

## Decision

1. **DataProvider extension:** added `createRecord({ collection, id?, data })`
   to the interface (Section 6B contract grows; Firestore adapter writes to
   the named collection, fixture adapter stays read-only). Forms/operations
   write through it — never the Firestore SDK directly.
2. **Guard order (submit):** same-origin → traffic rules → per-IP rate limit
   (hashed SHA-256 IP + RELAY_SECRET salt — raw IPs never stored) → size cap
   (256 KB JSON / 10 MB multipart) → honeypot (`gw_hp` non-empty → silent
   200) → min fill time (`MIN_FILL_TIME_MS` = 2 s) → optional reCAPTCHA v3
   (enabled per-folder via `webSettings.recaptcha.enabled`; verified against
   Google when `RECAPTCHA_SECRET_KEY` is set) → strict Zod payload.
3. **Payload contract:** JSON and multipart normalize into the SAME strict
   schema (`FormSubmitPayloadSchema`, lib/contracts/forms.ts):
   `{ formTypeId?, submittedAt, gw_hp, values }`. Clients can never pass
   destinationTable/hooks — server-side only.
4. **Form-type config:** loaded via the DataProvider from `system-items`
   objects matching `meta.slug === 'form-type-definition'` OR
   `data.type === 'json'`, matched by `data.formTypeId`/`id`/`contentId`
   (tolerant). Provides `destinationTable` + `afterSaveApiHooks` (URL
   strings or `{url}` objects). Default destination: `formTypeId` → `forms`.
5. **Record shape (saveForm-compatible):**
   `{ id, docId, name, formType, formKeyValues, serverTimeStamp (ISO),
   date_str (YYYY-MM-DD) }` — `users` destination adds `roles: ['customer']`.
6. **Hooks:** server-side axios GET (5 s timeout), same URL contract as
   Uniconhub. `Promise.all(...).catch()` — a failing hook NEVER fails the
   submission (hard rule).
7. **Upload:** multipart only; size cap 10 MB; MIME + extension allowlists
   (images/pdf/txt/zip); storage path `sites/<folderId>/uploads/<ts>-<name>`
   (folder from SITE config — never client-controlled); returns `{ url,
   path }` via `provider.uploadFile`.
8. **Tests:** a recording fake DataProvider (tests/api/forms-fakes.ts)
   captures `createRecord`/`uploadFile` calls and asserts the exact shapes —
   the same assertions run unchanged against the Firestore adapter when
   `FIRESTORE_EMULATOR_HOST` is available (no emulator binary in this
   environment). Coverage: record shape, hooks fire, hook failure doesn't
   fail submission, users roles, honeypot, rate limit (hashed keys), min
   fill time, origin, traffic rules, Zod rejection, size caps, multipart
   normalization, reCAPTCHA gating, upload allowlists.

## Consequences

- One guarded write path for forms (Section 14 hard rule); the client
  payload contract from C5 matches this server contract exactly.
- `webSettings.recaptcha` shape is documented here (folder-config toggle);
  extend the SiteWebSettings schema when the CMS confirms the real field.
- Rate-limit state is per-process (memory); multi-instance deployments add
  a shared store in C11.
