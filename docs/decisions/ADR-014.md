# ADR-014 — C14 feature batch: reusable sections, list widget, sharedCss, gw.ns, trace comment

Status: Accepted
Date: 2026-08-18

Context:
The v1.2→v2.0 feature review (8 legacy items) decided DO NOTHING for
Nunjucks, embedded style/script as the primary mechanism, and raw client
writes — and BUILD modern replacements for the remaining gaps: reusable
page composition (legacy blocks), a no-code list (legacy object-query-list),
site-wide shared CSS, a per-page script namespace (legacy window.MyPage),
and page traceability (legacy GW-PAGE-ID comments).

Decision (C14 / M20 — plan Sections 7.4, 11, 12, 13):
1. REUSABLE SECTIONS — page objects may carry
   `data.sections: [{cmsObjectType, objectId}]` (flat, max 20). The loader
   resolves each referenced object's own `htmlPage.code` IN ORDER via the
   DataProvider; missing / private (`rules.publicAccess === 'no'`) / draft
   (unless preview) sections are skipped with a pino `gw-section-skipped`
   warning — never fail the page. Sections contribute ONLY html/css/js (no
   SEO, hreflang or chrome). Depth guard is structural: sections inside
   section objects are never expanded (no recursion). `RenderPlan` carries
   `sections: PageSectionCode[]`; `ContentMount` injects section html first
   (in order), section css with a per-section `data-gw-css` dedupe key
   (`section-<objectId>`), and executes section js before page js.
2. LIST WIDGET — built-in `data-gw-app="list"` island (cmsObjectType,
   folder, filters, orderBy/orderDir, pageSize ≤ 200, language,
   fields[{field,label,format}], emptyText). Renders via `gw.db.query`;
   EVERY value via textContent (XSS-safe by construction); loading / empty /
   quiet-error states; live refresh via `gw.db.subscribe` when
   pageSize ≤ 50.
3. SHARED CSS — `default-settings.data.sharedCss` is injected into <head>
   with `data-gw-shared-css` BEFORE section/page css and removed with the
   page styles on SPA unmount. Site-wide, deduped.
4. RESERVED gw- PREFIX — the `gw-*` class prefix belongs to the platform
   shell, built-in widgets and sharedCss; page authors must never define
   `gw-*` rules (documented in the generator rules, not runtime-enforced).
5. GW.NS NAMESPACE — `gw.ns = context.ns || {}` in the SDK install: a fresh
   object per page visit / SPA navigation (the bootstrap reinstalls per
   navigation). Generator rule: attach page helpers to `gw.ns`, never rely
   on hoisted window functions.
6. AUTO TRACEABILITY COMMENT — the platform prepends
   `<!-- gw-page: <objectId> · slug: <slug> · lang: <language> ·
   updated: <ISO> · status: <status> -->` to the page container. Never
   contains hosts, secrets, preview URLs or admin paths. Authors must not
   emit GW-PAGE-ID-style comments.

Hard rules preserved: no Nunjucks, embedded style/script stays tolerated
but NOT primary, no raw client DB writes — writes stay on
operations/flows/forms/cart.

Consequences:
+ Editors compose pages from reusable section objects without duplicating
  markup; a no-code list is back with safe rendering; sites get consistent
  shared styles; page scripts get an isolated helper namespace; support can
  identify the rendered page object at a glance.
+ Trade-offs: sections are fetched per page render (N+1 reads, mitigated by
  the ≤20 cap and provider caches); section css/js share the page's mount
  lifecycle and must be idempotent like page code; sharedCss is admin-owned
  and must keep the gw- prefix discipline.
+ Changes later: if section reads become hot, cache section objects per
  site; a future sections-reorder/editor UI is CMS-side only.
