# ADR-011 — Realtime SSE, event bus, tag purging & observability (C11 / M7)

Status: Accepted
Date: 2026-08-15

Context:
Section 18 defines the cache-tag vocabulary and the publish webhook;
Section 20 requires structured JSON logs (request id, host, site, page,
latency) and error boundaries; Section 34 requires gw.db.subscribe
realtime, an event bus with outbound webhooks and a per-tenant audit log.

Decision:
- Realtime: `GET /api/subscribe` — Server-Sent Events, provider-agnostic.
  The stream feeds `added|modified|removed` events from
  `DataProvider.subscribe` (Firestore onSnapshot now, Supabase Realtime
  later) plus `gw-event` events from the in-process bus filtered by
  `folderId`. READ-ONLY: only change notifications are pushed, never data
  writes. Keepalive ping every 15s. `gw.db.subscribe` prefers EventSource
  and keeps the C7 polling fallback when EventSource is unavailable.
- Event bus (`lib/events/`): `emitSiteEvent` fans an event to (1) the
  in-process bus (SSE live UI + internal handlers), (2) an admin-compatible
  audit log — `event-log${tableExtension}` records keyed by event id, and
  (3) folder-configured outbound webhooks
  (`webSettings.outboundWebhooks: [{url, secret?, events?}]`), signed with
  `x-gw-signature: sha256=HMAC-SHA256(body, secret)` (default secret:
  RELAY_SECRET) + `x-gw-event` / `x-gw-event-id` headers. All three legs
  are best-effort — they NEVER fail the operation. The operations engine
  emits `operation.completed` and `hook.completed` after success.
- Caching: tag vocabulary `site-<folderId>` / `page-<objectId>` /
  `type-<appId>` / `host-<host>` (lib/cache/tags.ts). `POST /api/revalidate`
  guarded by the shared REVALIDATE_SECRET (`x-revalidate-secret` header)
  purges tags via `revalidateTag(tag, 'max')` (Next 16 two-arg purge);
  `site-*` purges ALSO clear the resolver memory caches
  (`getResolverStack().clearCaches()`) so folder/app config changes are
  served immediately. Unknown tag shapes are ignored; the route echoes the
  purged list.
- Observability: pino JSON logs (`lib/log/logger.ts`) with a hard redaction
  list (passwords, cookies, authorization, secrets/keys — censored as
  `[redacted]`; no secrets in logs, hard rule). `logRequest` emits one line
  per website request: requestId (x-request-id or generated), method, path,
  host, status, site (folderId), page (pageId), latencyMs (measured outside
  the React component body — the purity lint rejects Date.now during
  render). Error taxonomy (`lib/log/errors.ts`): auth / rate-limit /
  not-found / validation / upstream / internal with sanitized public
  messages; error boundaries: the (website) group keeps its error.tsx, a
  new root `app/error.tsx` covers /p/user.
- Vitest: `teardownTimeout: 30_000` — full-suite runs carry heavy
  firebase-admin import graphs and fork teardown occasionally exceeds the
  default.

Consequences:
- Realtime is per-node in-process; multi-instance fan-out needs Redis or
  provider-native channels later (documented limitation).
- Event log writes add one record per successful operation (included in
  operation tests' commit counts).
- revalidateTag purge in dev is a no-op for the data cache (dev has no ISR);
  resolver cache clearing is what makes dev purges observable.
