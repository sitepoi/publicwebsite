# ADR-015 — Widget island SSR contract (application-store html tools)

Status: Accepted
Date: 2026-10-05

Context:
Page builders embed application-store html tools as contract islands:

    <div data-gw-app="Food Ordering Cart" data-gw-config='{}'></div>

The library lives in the platform-owned object type
`website-html-tool-library-applicationstore` on the store host. Each
record carries `gwAppName`, `configSchema`, `ssrHtml`, `ssrEnabled` and
`code.{html,css,js}`. Before this ADR the platform only mounted islands
client-side (C12) and had no server-side notion of the catalog.

Decision (WIDGET ISLAND PUBLISH CONTRACT, SSR DEFAULT):
1. SERVER-SIDE CATALOG — `lib/render/widget-islands.ts` fetches the
   library at render time (never from the browser) via the store's v2
   API: GET `{GW_APP_STORE_API_URL|https://applicationstore.uniconhub.com/api/v2}/objects/website-html-tool-library-applicationstore?limit=200[&cursor=<lastId>]`
   with `x-api-key: <viewer key>` (scope objects:read — every v2 request
   must authenticate; key from the store CMS Manage → Settings → API
   Management, delivered to ops per environment as GW_APP_STORE_API_KEY).
   Response `{ success, mainObjectType, count, nextCursor, objects }`;
   nextCursor empty/null = last page; a 200 body with success:false is
   treated as a failure. 10s timeout, in-memory TTL cache
   (GW_APP_STORE_CACHE_TTL_MS, default 5 min). Fail-open: a failed fetch
   serves the previous successful catalog or an empty one — the store
   NEVER breaks the page (CMS-confirmed fail-soft precedent). Records are
   raw Firestore docs with NO top-level "data" wrapper — tool fields live
   under `productData.data_categoriesBased` (top-level/legacy `data` also
   tolerated, data_categoriesBased wins; `code` may be a JSON string).
   CONFIRMED FIELD TYPES: gwAppName/title/description/category/ssrHtml are
   STRINGS, configSchema + code{html,css,js} are nested OBJECTS,
   ssrEnabled is a BOOLEAN; data-gw-app matches gwAppName exactly
   (case/space-sensitive).
2. INVALIDATION — TTL-only is NOT acceptable (the cache key includes the
   PAGE version, not the widget version). The store must wire its publish
   path → triggerRevalidate → POST /api/revalidate; the website side
   clears the catalog cache on every successful revalidate call
   (`clearAppStoreCatalogCache`, injectable in handleRevalidate) so the
   next render refetches the catalog immediately.
3. SSR LAYER (default) — for each island, parse5-based (new dependency,
   server-only): ssrHtml → injected INSIDE the island after existing
   content + `data-gw-ssr="1"`; no ssrHtml → `data-gw-ssr="none"`;
   `ssrEnabled:false` → `data-gw-ssr="client"` (no server markup); unknown
   name OR store down → EMPTY island + `data-gw-ssr="none"` + pino
   `gw-widget-unknown` warning (marker semantics confirmed by the
   WebpageBuilder). Preview-only placeholder chips NEVER appear on
   publish. Scripts are stripped from the emitted islands so nothing
   executes early. The layer covers page content, sections and chrome.
   Output is DETERMINISTIC (no Math.random/time) — cache-safe.
4. CONTENTMOUNT — `serverHtml` renders the island SSR layer into the
   container for the first paint; `mountContent` then rebuilds the full
   page (client render wins, C12 unchanged). `widgetCss` is injected
   AFTER page css (dedupe `data-gw-widget-css` per name); `widgetScripts`
   run AFTER page js and BEFORE auto-mount, each MUST call
   `gw.apps.register` (idempotent, re-runs on SPA navigation). Tool
   runtime confirmed: plain scripts (IIFE via Blob URL — exactly our
   executeCode path), NO ES modules, NO top-level await, running against
   `window.gw` (NOT the CMS iframe's window.tool).
5. SDK — bootstrap context gains `appSchemas` (configSchema per used
   name; draft-07 keyword subset, no $schema); `mountOne` applies schema
   defaults for missing config keys (builders bake them into
   data-gw-config, but older/hand-edited pages need the platform
   fallback) and invalid `data-gw-config` JSON now mounts with `{}` +
   console warning + non-fatal `gw:app-error` (previously aborted).
6. BUILTINS — the C12 builtin widget names (`menu`, `cart`, … `list`)
   stay client-only: they are never resolved against the catalog.
7. CSS — `code.css` is appended after page css; tool-side rules:
   scoped under the widget's own wrapper class (e.g. .foc-app), `gw-*`
   rules FORBIDDEN, `--gw-color-*` variables allowed.
8. FIXTURES — `GW_DEV_FIXTURES=1` serves an in-memory catalog
   (`fixtureWidgetCatalog` + `createFixtureWidgetCatalogResolver`);
   the /widgets fixture page embeds `store-counter` (ssrHtml +
   configSchema), `store-static` (ssrEnabled:false) and `unknown-tool`.
   No platform-wide staging store exists — per-environment host mapping
   goes through GW_APP_STORE_API_URL (PROD v2 is the default).

Security/consistency preserved: island code is platform-authored library
code (trusted at build time); config values are DATA (widgets render via
textContent / gw.sanitize); SSR markup never executes scripts; unknown
names never crash the page.

Acceptance (unit + e2e): ssrHtml injection + data-gw-ssr markers in the
raw SSR HTML; deterministic island layer across renders; client-only
records render client-side; unknown names render empty "none" islands and
warn without breaking pages; invalid JSON mounts with {} + warning;
revalidate clears the catalog cache.
